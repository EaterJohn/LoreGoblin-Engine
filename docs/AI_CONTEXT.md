# AI_CONTEXT.md — читать первым

Точка входа для любой LLM (Claude, GPT, локальная модель), которая начинает или
продолжает работу над проектом. Автор курирует разработку и почти не пишет код
сам: весь код пишет ИИ. Документация в `docs/` это твоя единственная память о
проекте между сессиями.

**Не изучай весь репозиторий.** Для твоей задачи нужно три-пять файлов. Какие,
написано в `README.md` (таблица «Задача → пакет файлов»).

## Как начать (для ИИ)

1. Прочитай этот файл и `GOLDEN_RULES.md` (это занимает минуту).
2. Прочитай `STATUS.md`: что реально работает, что открыто.
3. Возьми пакет файлов под свою задачу из `README.md`. Читай только его.
4. В `DECISIONS.md` читай реестр сверху и только записи, касающиеся задачи. Не
   предлагай заново то, что там отклонено.
5. Незнакомый термин (слой, модуль, мод, ядро, tier): `GLOSSARY.md`.
6. Чего-то не хватает для задачи: **спроси владельца**, не додумывай.
7. В конце сессии: принято решение или добавлена значимая фича: запись в
   `DECISIONS.md` (и строка в реестр), обновить `STATUS.md`; при смене файлов
   `PROJECT_STRUCTURE.md`; запустить `python tools/docs_index.py`.

Файлы `ideas/` и `vision/` это идеи и ориентиры, не решения и не описание кода.
Открывай их, только если пакет задачи на них указывает. Не считай их
реализованными.

## Как начать (для человека)

Если ИИ работает в репозитории (Claude Code, Codex), он сам прочитает `AGENTS.md`.
Если это обычный чат без доступа к файлам, скинь первым сообщением `AGENTS.md` и
`docs/STATUS.md`, а затем файлы пакета под задачу. `INDEX.md` содержит список всех
документов с условиями чтения.

## Проект одной строкой

**LoreGoblin** — детерминированная модульная основа для симуляций, которые строит
и запускает ИИ. Ядро проверяет и фиксирует, модули считают, LLM предлагает и
объясняет. Первый эталонный мир: текстовая RPG **ALLIZIUM** (world pack, идёт с
движком по умолчанию), а не название движка. Курс принят записью #ENG-024;
подробности в `vision/STRATEGY.md`. Пока реализован только вертикальный срез RPG,
не вся модульная основа.

## Главные принципы (полный список: `GOLDEN_RULES.md`)

> **Engine знает, что существует. LLM решает, что делать и как это описать.**
> **PLAYER CLAIM ≠ CANON.**
> **Engine не должен знать ни про один конкретный мир.**

Источник истины — SQLite через `engine/`. LLM никогда не меняет состояние мира
напрямую, только через tool calls, которые обрабатывает `ActionAPI`. Весь лор это
данные, а не код. Остаточные протечки (например, `money.silver`) записаны как
техдолг в `STATUS.md`.

## Жёсткие правила для кода, который пишет ИИ

- SOLID и модульность. Код в `engine/` не знает о сеттинге, персонаже, предмете.
  Тестовые данные лежат в `data/worlds/`, не в модуле.
- Любое изменение, влияющее на архитектуру (новая таблица, слой, формат
  хранения): сначала запись в `DECISIONS.md`, потом код.
- Код будет читать другая ИИ в другой сессии без общего контекста. Пиши так,
  будто объясняешь незнакомому разработчику.
- Проект open-source и moddable: не привязывай ничего к личным предпочтениям
  мира ALLIZIUM, если это можно вынести в конфиг или данные.
- Моду или модулю не хватает ядра: не обходи. Дерево решений в
  `GOLDEN_RULES.md`, правило 7.
- Не пиши в документах «реализовано» без ссылки на код или тест
  (`GOLDEN_RULES.md`, правило 10).
