# MODDING.md — как собрать свой мир на движке

**Что реализовано:** world packs (`world.json`, `system_prompt.txt`, `rules_preset`) загружаются через `WorldEngine.load_world()` (`DECISIONS.md` #ENG-015, #ENG-021).

**Что только спроектировано, в коде нет:** `manifest.json`, `installed_mods.lock.json`, `data/mods/`, зависимости и версии модов, генератор диаграмм (#ENG-011). Эти разделы помечены ниже. Планы по слоям, порядку загрузки и конфликтам: `vision/MODULES_AND_LAYERS.md`.

## Идея

Движок (`engine/`) ничего не знает о конкретном сеттинге. Мир — это папка
с данными. Чтобы сделать свой мод, не нужно трогать код движка вообще.

```text
data/worlds/
  allizium/              ← мир по умолчанию, идёт вместе с движком
    world.json
    system_prompt.txt
    world.db              ← создаётся автоматически, в .gitignore
  my_scifi_setting/        ← пример стороннего мода
    world.json
    system_prompt.txt
```

Запуск конкретного мира:

```powershell
python main.py --world my_scifi_setting
```

## Из чего состоит мир-пак

### `world.json` — обязателен

Стартовое состояние мира: сущности, начальная локация, начальное время,
деньги игрока. Формат — данные, которые загружает `engine/world.py::load_world()`.:

```json
{
  "rules_preset": "standard",
  "world_time": "Day 1 12:00",
  "start_location_id": "some_location",
  "player": {
    "id": "player",
    "name": "Имя по умолчанию",
    "location_id": "some_location",
    "stats": { "STR": 10, "CON": 10 },
    "starting_money": 100
  },
  "entities": [
    {
      "id": "some_location",
      "type": "location",
      "name": "Название локации",
      "location_id": "parent_area_or_null",
      "data": { "contents": ["item_1", "npc_1"] }
    },
    {
      "id": "item_1",
      "type": "item",
      "name": "Название предмета",
      "location_id": "some_location",
      "data": { "price": 10 }
    }
  ]
}
```

`rules_preset` — id файла из `data/rules/presets/` (имя, не путь; применяется при
каждой загрузке мира, см. `ARCHITECTURE.md` и #ENG-021).

Важно: набор `stats` — свободный, движок не привязан к
STR/CON/DEX/PER/WIL/INT/CHA/Luck/Eth, это можно заменить на любые
атрибуты сеттинга (например, для sci-fi — `TECH`, `REFLEX`, `WILL`).

### `system_prompt.txt` — опционален

Надстройка к общим правилам движка (тон, атмосфера, специфика сеттинга).
Общие правила ("не выдумывай предметы/NPC/события, используй инструменты
для действий, меняющих мир") заданы один раз на уровне движка и одинаковы
для всех миров — их дублировать в `system_prompt.txt` не нужно.

## Манифест мода — `manifest.json` (спроектировано, не реализовано)

Обязателен для любого мода (не для мира `allizium` по умолчанию — он
встроенный). Машиночитаемое описание зависимостей — источник истины,
из которого при необходимости генерируется диаграмма (см.
`docs/DEPENDENCY_GRAPH.md`). Решение и обоснование — `DECISIONS.md` #ENG-011.

```json
{
  "id": "my_scifi_setting",
  "version": "1.2.0",
  "requires_engine": ">=0.3.0",
  "depends_on": [
    {"id": "core_weapons_pack", "version": ">=2.0.0"}
  ],
  "provides": {
    "entities": ["laser_rifle", "space_station_alpha"],
    "tools": []
  }
}
```

Поля:

| Поле | Смысл |
|---|---|
| `id` | Уникальный идентификатор мода, совпадает с именем папки в `data/worlds/` или `data/mods/` |
| `version` | SemVer |
| `requires_engine` | Минимальная совместимая версия движка |
| `depends_on` | Список других модов, без которых этот не запустится |
| `provides.entities` | ID сущностей, которые мод добавляет — нужно для диагностики конфликтов имён |
| `provides.tools` | Если мод добавляет свои tools (см. ограничение ниже) |

## Lock-файл сборки — `installed_mods.lock.json` (спроектировано, не реализовано)

Фактическое разрешённое состояние **конкретной установленной сборки** —
не то, что мод *хочет*, а то, что реально стоит и в каких версиях.
Генерируется движком при установке/обновлении модов, не редактируется
руками.

```json
{
  "engine_version": "0.3.1",
  "resolved": [
    {"id": "allizium", "version": "1.0.0", "depends_on": []},
    {"id": "core_weapons_pack", "version": "2.1.0", "depends_on": []},
    {"id": "my_scifi_setting", "version": "1.2.0", "depends_on": ["core_weapons_pack@2.1.0"]}
  ]
}
```

Это и есть тот "снимок сборки", который игрок присылает при поломке —
не картинка, а точные данные: что стоит, в каких версиях, кто от кого
зависит. По нему ИИ ищет конфликт версий напрямую, без диаграммы.

## Диаграммы — генерируются по запросу, не хранятся как факт (генератор не написан)

Диаграмма (Mermaid) — это производная от `manifest.json` +
`installed_mods.lock.json`, а не отдельный источник истины. Правила:

- Диаграмма никогда не редактируется руками и не коммитится как
  "актуальное состояние" — она либо генерируется скриптом на лету, либо
  не хранится вообще.
- При большом числе модов (условно 10+) рисовать граф целиком
  бессмысленно — нужен **отфильтрованный подграф**: конкретный мод +
  его прямые зависимости (глубина 1–2), а не весь проект сразу.
- Подробности генерации — `docs/DEPENDENCY_GRAPH.md`.

## Чего мод НЕ может

- Мод не может добавлять новые tools/механики — это требует изменений в
  `engine/actions.py` и `engine/world.py`, то есть уже не "мод", а форк
  движка. Если механика нужна многим модам — это повод предложить её как
  фичу движка (через `DECISIONS.md`), а не решать на уровне одного мода.
  (Поле `provides.tools` в манифесте зарезервировано на будущее, если это
  решение пересмотрят — сейчас должно быть пустым.)
- Общее правило: мод (и будущий модуль) пользуется только тем, что ядро уже
  предоставляет. Чего в ядре нет, мод добавить не может: это предложение в ядро
  через `DECISIONS.md` (решение владельца проекта, 2026-10-01).
- Мод не может обходить принцип `PLAYER CLAIM ≠ CANON` — это инвариант
  движка, а не настройка мира.

## Чек-лист для тех, кто собирает мод

1. Скопировать `data/worlds/allizium/` как шаблон.
2. Переписать `world.json` под свой сеттинг: сущности, локации, статы,
   стартовые деньги/ресурсы.
3. Когда манифест будет реализован (#ENG-011): добавить `manifest.json` с
   корректными `id`, `version`, `depends_on`. Сейчас шаг пропускается.
4. При желании — свой `system_prompt.txt` с тоном мира.
5. Запустить `python main.py --world <имя_папки>` и проверить `/state`,
   `/inventory`, `/tools`.
6. Прогнать `pytest` — `tests/test_engine.py` завязан на конкретный демо-мир
   Allizium, для мода понадобятся свои тестовые сценарии (это отдельная
   задача движка — параметризовать тесты по миру, не решено).

## Запланировано (не реализовано, см. `ideas/IDEAS_INDEX.md`)

- Язык ввода и мира как параметр мода (`locale`), лексикон парсера как данные мода.
- Слои и категории модулей, отношение `refines`, порядок загрузки, конфликты:
  `vision/MODULES_AND_LAYERS.md`.
- Параметризация тестов по миру (в списке «чек-листа»: пока не решено).

## Известный технический долг

Название валюты (`silver` в схеме `money`) сейчас зашито в
`database.py` — для мода без "серебра" как понятия это протечка
реализации. Зафиксировано как технический долг, не блокирует MVP.
