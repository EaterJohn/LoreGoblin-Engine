# Модули, слои, зависимости, конфликты

Статус: видение и кандидат в решение (`../ideas/IDEAS_INDEX.md`, пункт 8). Реализовано
только подключение мира как данных. Манифест и lock-файл спроектированы (#ENG-011).

## Чего хочет проект

Модульная система в духе Skyrim: категории, зависимости, порядок подключения,
разрешение конфликтов. Модули бывают слоистыми: более детальный слой разворачивается
из более грубого (молекулярная химия не существует без обычной химии, потому что
она промежуточное звено для следующей развёртки).

## Ограничение расширений

Мод пользуется только тем, что ядро уже предоставляет. Чего в ядре нет, мод
добавить не может: предложение идёт в ядро через `DECISIONS.md` (подтверждено
2026-10-01, `../MODDING.md`).

> **Уточнение (#ENG-026, предложено):** правило выше относится к **модам** (данные).
> **Модуль** (код под контрактом, `MODULE_CONTRACT.md`) может добавлять свои tools и
> ограничения через контракт, но не обходит ядро (`../GOLDEN_RULES.md`, правило 7).

## Слой и категория

Каждый модуль объявляет **слой** (откуда он зависит) и **категорию** (что он такое).
Допустимо зависеть только от слоёв ниже.

```text
core                      примитивы (CORE_PRIMITIVES.md)
 └─ materials            вещества, свойства
     └─ chemistry         реакции, составы
         └─ molecular_chemistry    уточняет chemistry
 └─ spatial               пространство
 └─ agents                драйверы, когниция
 └─ domain: magic, economy, ...    опциональные домены
 └─ world packs           данные мира, верхний слой
```

Имена слоёв примерные. Реальный список появится вместе с первым модулем, которому
он нужен.

## Отношения между модулями

| Отношение | Смысл |
|---|---|
| `depends_on` | без этого модуль не запустится (есть в манифесте) |
| `refines` | детальный слой над базовым: базовый **работает сам**, детальный требует базового |
| `conflicts_with` | явная несовместимость |
| `load_after` / `load_before` | порядок, если зависимости его не определяют |

Принцип `refines`: грубое представление никогда не ломается, когда детальный модуль
не подключён (`CORE_PRIMITIVES.md`, пример с ядом).

## Кандидат: поля манифеста

Расширение `manifest.json` из `../MODDING.md`. **Это эскиз, формат не решён.**

```json
{
  "id": "molecular_chemistry",
  "version": "0.1.0",
  "requires_engine": ">=0.4.0",
  "category": "domain",
  "layer": "chemistry",
  "depends_on": [{"id": "chemistry", "version": ">=1.0.0"}],
  "refines": ["chemistry"],
  "conflicts_with": [],
  "load_after": ["chemistry"]
}
```

## Порядок загрузки и конфликты

1. Топологическая сортировка по `depends_on` и `refines`, затем `load_after/before`.
2. Проверка версий (`requires_engine`, версии зависимостей) по lock-файлу.
3. Конфликт (два мода правят одну сущность или правило) это **ошибка загрузки**.
   «Последний выигрывает» допускается только для явного патч-мода, который заявил
   приоритет.
4. Битый или конфликтующий мод не портит сохранение: загрузка отклоняется до записи
   в БД (`RELIABILITY_AND_PERFORMANCE.md`).

## План по ступеням (чтобы не строить лишнее)

| Ступень | Что | Условие входа |
|---|---|---|
| 0 | world pack как данные | **сделано** |
| 1 | манифест + lock-файл, топосортировка, проверка версий, ошибка при конфликте | реальный второй мод |
| 2 | слои, `refines`, `load_after` | реальный доменный модуль |
| 3 | патч-моды и приоритеты | реальная потребность в переопределении |

Каждая ступень проходит фильтр из `../ideas/IDEAS_INDEX.md`.

## Карта слоёв движка (из исходных заметок)

Концептуальное направление зависимостей, не раскладка пакетов Python:

```text
CORE (Entity / State / Event / Action / Rule)
  ├─ Semantic ── Spatial ── Events
  └─ Affordances → Actions → Effects → World State
        ├─ Agents ── Simulation (Magic, Chemistry, Biology) ── Generation
        └─ Knowledge/Memory → Narrative / Clients
```

Один мир может использовать `Core + Economy + Magic`, другой
`Core + Chemistry + Biology + Manufacturing`; Core валиден в обоих случаях.
Диаграммы зависимостей конкретных модов (по манифесту) см. `../DEPENDENCY_GRAPH.md`.
