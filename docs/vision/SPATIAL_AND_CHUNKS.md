# Пространство, 3D-чанки, перемещение

Даже если первый продукт это текстовая RPG, архитектура не должна делать
полноценную пространственную симуляцию невозможной. Нарратив и пространство это разные
разрешения одного мира.

## Что говорят идеи и что говорит видение

| Источник | Позиция |
|---|---|
| `../ideas/WORLD_MODEL_IDEA.md` §8 | для текстовой RPG начать с **графа локаций и полос дистанции** за интерфейсом `SpatialModel`, координаты подставить позже |
| `../ideas/AFFORDANCES_AND_PERSISTENCE_IDEA.md` §8 | локации это **факты, влияющие на разрешение** (укрытие, видимость, проходимость, вместимость), а не рельеф; зона генерируется один раз и фиксируется в каноне |
| это видение | долгосрочно гибрид: непрерывное 3D + семантический граф + возможности актёра |

Это не противоречие, а порядок: сначала интерфейс `SpatialModel` с реализацией на
графе и фактах, потом (если понадобится) реализация на 3D за тем же интерфейсом.

## Гибридное представление

Один граф недостаточен: он не выражает полёт над лесом, подкоп под горой, прыжок со
скалы, плавание, телепортацию. Одни координаты тоже недостаточны: они не говорят,
возможно ли движение. Поэтому:

```text
3D непрерывное/физическое пространство  +  семантический граф связности  +  возможности актёра
```

Примитивы (потенциальные): координаты, векторы, преобразования, ориентация,
расстояние, объём, поверхность, топология, вложенность, коллизии, линия видимости,
высота, связность.

## Перемещение это запрос к миру

```text
возможности актёра + способ движения + среда + пространственные правила → возможность и цена
```

| Актёр + способ + цель | Результат |
|---|---|
| человек + ходьба + гора | возможно, дорого |
| человек + полёт + гора | возможно, другой путь и цена |
| человек + телепорт + гора | напрямую, если правила позволяют |
| рыба + ходьба + гора | невозможно |

Движение не является жёстким свойством локации.

## Чанки

```text
World → Chunk[x,y,z]
```

Возможные данные чанка: seed, параметры генерации, ландшафт, важные сущности,
структуры, ресурсы, выходы и связи, локальное состояние, состояние симуляции,
ссылки на историю, состояние разрешения.

Жизненный цикл: сгенерировать → расширить → симулировать → выгрузить → загрузить →
продолжить с сохранённого состояния → расширить дальше. **Существующий канон
побеждает свежую генерацию** (`PRINCIPLES.md`).

Разрешение чанка: макро → ландшафт и важные объекты → локальные структуры → детальные
объекты → физическая геометрия. Не каждому чанку нужен максимум.

## Открытые вопросы

- Когда граф перестаёт хватать и нужна реализация `SpatialModel` на координатах.
- Как «мир конечен, зона фиксируется» (идеи) совмещается с бесконечными чанками.
- Единицы и ориентация, если появятся координаты.
