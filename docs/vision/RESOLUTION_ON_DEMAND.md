# Resolution on Demand (разрешение по требованию)

Гипотеза ядра. Статус: направление; держать как принцип, не как огромную подсистему.

> Детали растут тогда, когда действие, запрос, событие или требование системы
> реально в них нуждается. Спусковым крючком служит не только наблюдение игроком.

> Не считать деталь, которую никакая текущая задача не использует. Но у любого
> грубого представления должен быть путь к достаточной детали.

## Пример

Пиво: `liquid, drinkable, price, basic effects`. Химический анализ потребует
`composition, substances, concentration, contaminants, reactions`.

## Уровни материализации объекта (`M0–M5`)

Обозначения предложены в `../GLOSSARY.md`, чтобы не путать с представлением `L0–L2`.
Уровни ориентировочные, не финальная реализация.

| Уровень | Что |
|---|---|
| M0 | семантический объект |
| M1 | функциональная структура |
| M2 | физические компоненты |
| M3 | материальный состав |
| M4 | точная геометрия |
| M5 | детали производства |

Важно: **детерминированный путь от грубого к достаточно детальному**.

## Спусковые крючки

Действие, осмотр, крафт, бой, химия, физика, производство, знание NPC, событие
симуляции, пространственная коллизия, перемещение, разрушение, измерение.

## Не только объекты

NPC (когнитивная детализация, `AGENTS_AND_COGNITION.md`), экономика, экология,
локации, история, магия, химия. Пример NPC: далёкое население остаётся агрегатом;
когда событию нужен конкретный человек: агрегат → материализовать индивидуума →
назначить совместимую историю → продолжить симуляцию.

## Открытые проблемы

Уровни и их число; триггеры; требуемая глубина; сохранение последствий;
безопасность агрегации; запросы между модулями; детерминированность материализации;
цена хранения; защита от разгона детали (бюджеты и лимит глубины:
`RELIABILITY_AND_PERFORMANCE.md`).
