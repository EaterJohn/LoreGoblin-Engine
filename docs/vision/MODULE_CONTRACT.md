# Контракт модуля и паспорт

Статус: принято как направление (#ENG-026); формат манифеста пока рабочая схема. Расширяет эскиз манифеста из
`MODULES_AND_LAYERS.md` и #ENG-011. Формат не решён, это рабочая схема.

## Мод и модуль

| | Мод / world pack | Модуль |
|---|---|---|
| Что это | данные | код под контрактом |
| Примеры | `data/worlds/allizium/` | физика, химия, магия |
| Исполняемое | нет | да, в песочнице |
| Может добавлять tools | нет | да, через контракт |
| Паспорт | `manifest.json` (#ENG-011) | манифест + `MODULE.md` + тесты |

## Паспорт модуля

Каждый модуль лежит в своей папке:

```text
modules/<id>/
  manifest.json     машиночитаемое (формат ниже)
  MODULE.md         развёртка для людей и ИИ: что внутри, как работает, пределы
  src/              код
  tests/            unit-тесты автора
  conformance/      ссылка на набор контракта, который модуль обязан пройти
  oracles/          независимые эталоны (аналитические решения, данные)
```

### `manifest.json` (эскиз)

```json
{
  "id": "physics_kinematics",
  "version": "0.1.0",
  "requires_engine": ">=0.5.0",
  "tier": 0,
  "tags": ["physics", "mechanics", "motion"],
  "provides": [{"contract": "physics.motion", "version": "1.x"}],
  "requires": [{"contract": "kernel.time", "version": "1.x"}],
  "constraints": ["physics.energy_conservation"],
  "units": {"length": "m", "time": "s", "mass": "kg"},
  "determinism": {"uses_random": false, "uses_wall_clock": false, "float_policy": "fixed_step_f64"},
  "permissions": {"reads": ["entity.position", "entity.velocity"], "writes": ["effect.move"]},
  "tests": {"unit": "tests/", "conformance": "physics.motion@1", "oracles": "oracles/"}
}
```

### `MODULE.md` (структура)

1. Одна строка: что делает.
2. Развёртка: ключевые понятия, как устроено внутри, формулы и допущения.
3. Пределы применимости: где модуль перестаёт быть верным.
4. Примеры вызова и ожидаемого результата.
5. Как запустить тесты и эталоны.

Теги и поля манифеста индексируются в реестр (`tools`-генератор), поиск идёт по
тегам и по `provides/requires`.

## Уровни доверия

| Tier | Название | Права | Как достигается |
|---|---|---|---|
| 0 | карантин | только предлагает; пробный прогон; в канон не пишет | любой новый модуль (в том числе от ИИ) |
| 1 | проверенный | пишет в канон через конвейер, в песочнице | пройден conformance-набор контракта + независимые эталоны + паспорт |
| 2 | reference | официальный, поддерживается проектом | проверен длительной эксплуатацией и ревью владельца |

Модуль tier 2 не может зависеть от tier 0. Понижение автоматическое при сбое
инварианта (`TRUST_AND_ROLLBACK.md`).

## Что проверяется для повышения

- **Conformance-набор контракта.** Общий для всех реализаций контракта
  `physics.motion`. Пишется отдельно от модуля.
- **Эталоны.** Аналитические решения, законы сохранения, известные данные,
  сторонние симуляторы. Автор модуля их не выбирает.
- **Дифференциальный тест.** Две реализации одного контракта на одних входах:
  расхождение сверх допуска это сигнал, кто из них прав, решают эталоны.
- **Детерминизм.** Повторный прогон даёт тот же хэш состояния.
- **Правило для ИИ-модулей.** Тесты, сгенерированные тем же ИИ, что написал
  модуль, считаются документацией, но не доказательством.

## Воронка вкладов (золотое правило гоблина для новичков)

Человек может ничего не знать о коде и движке, ему достаточно описать задачу
для LLM. Но любой вклад идёт по одному пути: паспорт → карантин → набор
контракта → эталоны → повышение. Обратная связь на каждом шаге в формате
объяснимого отказа (`CONSTRAINTS.md`), поэтому новичок и ЛЛМ видят, что именно
исправить.

## Реестр

Отдельный git-репозиторий: папки модулей и сгенерированный индекс по тегам. Сайт
не нужен, пока нет модулей и спроса, и его гибель не должна ломать экосистему
(`PRECEDENTS.md`: связка движка и сервиса провайдера).

## Открытые вопросы

- Реальная песочница для Python-кода (подпроцесс, ограничение прав, WASM).
- Язык контрактов: JSON Schema, Protocol-классы, смесь.
- Версионирование контрактов и миграции при обновлении модуля.
- Как контракт задаёт единицы и точность (урок ROS).
