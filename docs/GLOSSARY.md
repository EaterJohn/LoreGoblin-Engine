# GLOSSARY.md — термины и оси, которые нельзя смешивать

Правило: одно определение на термин. Новое слово сначала ищи здесь. Колонка
«Статус» говорит, закреплён термин или это предложение, ждущее подтверждения.

## 1. Канон и слои знания

| Термин | Значение | Статус |
|---|---|---|
| **CANON** (канон) | то, что истинно в мире: SQLite `entities`, `world_state`, `events` | закреплён |
| **PLAYER CLAIM** | то, что сказал игрок; не факт, пока не подтверждён каноном (`PLAYER CLAIM ≠ CANON`) | закреплён |
| **NARRATION** (нарратив) | то, что рассказала LLM; подача, не источник истины | закреплён |
| **Проекция** | производное представление лога событий (память, знания, summary) | идея |
| **Прецедент** | зафиксированное решение по непокрытому случаю | идея |

### Три описания слоёв знания: как они соотносятся

В проекте есть три схемы. Это **предложение соответствия**, владелец не подтвердил.

| `ARCHITECTURE.md` | `ideas/EVENTS_AND_KNOWLEDGE_IDEA.md` §5 | заметки `vision/` (архив) |
|---|---|---|
| CANON | канон (что было на самом деле) | CANON |
| KNOWN, для NPC | «что дошло» + «как запомнилось» (два слоя поверх канона) | NPC KNOWLEDGE |
| KNOWN, для игрока | нет отдельного слоя (игрок получает через нарратив) | PLAYER KNOWLEDGE |
| INFERENCE | нет аналога | нет аналога |
| PLAYER CLAIM | нет аналога (в идеях выражено правилом «игрок действует, а не объявляет реальность») | нет аналога |
| NARRATION | нарратив (рендер) | NARRATIVE |

## 2. Оси детализации («LOD» значит пять разных вещей)

| Ось | Вопрос | Пример | Обозначение |
|---|---|---|---|
| **Представление** | сколько показать LLM | L0 строка / L1 карточка / L2 досье | `L0–L2` (закреплено, идеи) |
| **Материализация** | индивидуален ли объект | лес-агрегат → конкретное дерево; стул: смысл → компоненты → материал → геометрия | `M0–M5` *(предложение; в архиве назывались `L0–L5`, что совпадало с представлением)* |
| **Гранулярность разрешения** | массово или индивидуально | метеорит в толпе | без обозначения |
| **Вес доступа** | насколько доступно воспоминание | забывание как вес, не удаление | без обозначения |
| **Стоимость симуляции** | шагать или пересчитать целиком | горение: скорость и условия остановки | без обозначения |
| **Когнитивная детализация** | насколько глубоко «думает» агент | реакция → память и цели → убеждения и язык → идентичность и культура | `C0–C3` *(предложение; в архиве «Level 0–3»)* |

Правило: в документах всегда указывай, **какая ось** имеется в виду.

## 3. Модуль, мод, черта: разные вещи под похожими словами

| Термин | Значение |
|---|---|
| **Python-модуль** | файл кода (`engine/world.py`); так называй, когда речь про код |
| **Мод / world pack** | папка с данными, подключаемая к движку (`data/worlds/<n>/`); сейчас реализован как мир |
| **Доменный модуль / слой** *(vision)* | расширение движка по области (химия, магия, экономика), подключается как мод со слоем и зависимостями; см. `vision/MODULES_AND_LAYERS.md` |
| **Trait / черта** | набор возможностей сущности (`prayer_site`, `wood_source`) |
| **Состав (composition)** | из чего сделано вещество (порох = 5 компонентов в пропорции) |
| **Component (ECS)** | технический термин реализации; в документах пока используй «черты» и «состав» |

Новые термины основы (kernel, tier, паспорт) см. раздел 6 ниже.

Правило расширения: мод/модуль пользуется только тем, что ядро уже предоставляет
(кандидат в решение, подтверждено владельцем 2026-10-01, `MODDING.md`).

## 4. Действия и возможности

| Термин | Значение | Статус |
|---|---|---|
| **Tool** | функция, которую LLM может вызвать; описана в `engine/actions.py` | реализовано |
| **Tool surface** | какие tools видит LLM сейчас (зависит от локации и сессии) | реализовано (#ENG-013, #ENG-019) |
| **`allow_to`** | список действий, которые сущность допускает; сейчас статические данные мира (`"trade"`) | реализовано |
| **Affordance** (аффорданс) | заявленная точка входа действия: что можно делать с объектом; обобщение `allow_to` | идея, решение не принято |
| **Capability** (возможность актёра) | что умеет сам актёр (летать, плавать, телепортироваться); не то же, что аффорданс объекта | vision |
| **Driver** (драйвер) | то, что двигает NPC к поведению (жадность, страх…); вес меняется контекстом | идея |
| **Archetype / instance** | шаблон с умолчаниями и ограничениями / сгенерированный экземпляр | идея |
| **Resolution on Demand** | детали считаются, только когда задаче нужна эта глубина | идея |
| **Набор приёмки** | мини-миры в тестах, которые должны собираться без правок ядра | идея |

## 6. Модульная основа (с #ENG-024; статус терминов: предложение, #ENG-026)

| Термин | Значение |
|---|---|
| **Kernel** | минимальное домен-нейтральное ядро: идентичность, состояние, события, транзакции, ограничения, время, seed, реестр модулей (`vision/KERNEL_AND_SUBSYSTEMS.md`) |
| **Standard-подсистема** | официальная подсистема над kernel (Space, Materials, Agents…), заменяемая, с контрактом |
| **Модуль** (в смысле основы) | код под контрактом с паспортом; отличать от Python-модуля и от мода |
| **Мод** | данные без исполняемого кода (world pack) |
| **Контракт** | что модуль предоставляет и требует, версия, единицы, ограничения |
| **Паспорт** | `manifest.json` + `MODULE.md` + тесты модуля (`vision/MODULE_CONTRACT.md`) |
| **Tier** | уровень доверия: 0 карантин, 1 проверенный, 2 reference |
| **Conformance-набор** | общий набор тестов контракта, обязательный для всех его реализаций |
| **Эталон (oracle)** | независимый источник правильного ответа: аналитика, законы сохранения, сторонний симулятор |
| **Пробный прогон (dry-run)** | применение изменения на изолированной копии до фиксации |
| **Хэш состояния** | контрольная сумма состояния после каждой фиксации; находит расхождение при воспроизведении |
| **Логическое время** | целое время ядра, не связанное с системными часами; порядок событий задаётся ключом `(время, фаза, приоритет, номер)` |
| **Эталонный мир** | RPG ALLIZIUM в роли стенда для проверки абстракций (`vision/STRATEGY.md`) |
