## 1. Проблема, которую это решает

Симулятор реальности через движок грозит чудовищным числом состояний.
Перечислять «объект × действие × результат» нельзя. Экономия приходит из
трёх независимых вопросов к любому понятию мира:

| Вопрос | Механизм |
|---|---|
| Нужно ли **сохранять**? | значимость (раздел 3) |
| Нужно ли, чтобы объект был **индивидуальным**? | материализация (`WORLD_MODEL_IDEA.md`, раздел 5) |
| Нужно ли **считать сейчас**? | ленивый пересчёт, LOD симуляции |

## 2. Аффордансы

Схема: **AFFORDANCE → ACTION → CONSEQUENCE**.

- **Capability:** что объект в принципе позволяет (церковь: молиться; дерево:
  рубить; лесопилка: обрабатывать дерево).
- **Availability:** доступно ли сейчас (станок сломан, affordance существует,
  но недоступен).
- **Requirements:** что нужно (топор, выносливость).
- **Consequences:** что может измениться (дерево +3, выносливость −10,
  состояние дерева повреждено).

Действие может быть валидным и **не менять мир** («молюсь», последствий нет).

Как не завести две параллельные системы:
- Аффорданс это **заявленная точка входа** для частых глаголов
  (рубить, открыть, молиться). Его по умолчанию **выводят из архетипа и тегов**;
  явный список на экземпляре как переопределение.
- Эмерджентные взаимодействия (бочка + огонь → воспламенение) идут через теги и
  воздействия (`WORLD_MODEL_IDEA.md`), а не через список аффордансов.
- Список аффордансов в текущем состоянии это «закрытый мир» для
  детерминированного парсера (`INTENT_PARSER_IDEA.md`): он сопоставляет слова
  именно с ним.
- Продолжает линию `allow_to` из #ENG-019, но шире.

Универсальные действия есть у всего (осмотреть, подойти, послушать). Типовые
появляются из архетипа, контекстные из состояния (горящее дерево → потушить),
эмерджентные из комбинации тегов.

Общие механики последствий (минимальный набор): повредить, потребить,
произвести, преобразовать, переместить, уничтожить, создать, изменить
состояние, изменить отношение, изменить ресурс. Одни и те же механизмы
обслуживают «нарубить дерево», «обработать бревно», «сломать дверь».

## 3. Значимость: что сохранять

Канон не равен «всему, что произошло». Тремя уровнями:

| Уровень | Что | Срок |
|---|---|---|
| Эфемерное | мелочи («сел», «осмотрел», «помолился») | короткий кольцевой буфер с TTL, не канон |
| Событие | важное действие с последствиями, идёт в лог и суммаризацию | постоянно, с весом важности |
| Состояние | изменения свойств сущностей, отношений, ресурсов (`door.state = broken`, `npc.alive = false`) | постоянно, канон |

Правила:
- Значимость задаётся **данными действия/последствия**, а не решается моделью
  на ходу.
- Буфер эфемерного нужен, чтобы через минуту сработало «ты сидел на моём
  стуле», но это не превращает всё в канон.
- Канон хранит: состояния, постоянные сущности, постоянные отношения, важные
  события. Не «игрок моргнул».

## 4. Выбор метода

Действие задаёт **намерение** («режу дерево»), метод необязательно.
Метод назван (мономолекулярная нить), значит берём его. Не назван, тогда
движок выбирает детерминированным правилом (самый дешёвый из достаточных,
расходуемое последним) по возможностям актора. Нет подходящего метода:
действие не удаётся. Автовыбор редкого дорогого предмета без спроса
нежелателен (лучше спросить).

## 5. Прерывания как данные мира

Состояния автомата делятся на классы, прописанные в world pack:

- **Мягкие** (торговля, диалог, осмотр): прерываются любым другим действием.
- **Жёсткие** (бой, падение, смерть): прерываются только заданными событиями
  (`combat`: смерть или бегство).
- **Атомарные** (удар, шаг): не прерываются.

Очередь действий: цепочка действий из одной фразы («атакую, потом
отступаю») выполняется по одному с проверкой состояния между ними.

## 6. Роли LLM (уточнение)

- **Оркестратор LOD это код,** не LLM: он решает, какой уровень детализации
  нужен сейчас. В одном из черновиков он назван «World Orchestrator»: так
  называть можно, но реализация детерминированная.
- **Второй LLM, если он появится:** планировщик **атомарных шагов**, а не арбитр
  исходов. Нестандартную фразу («залью камень водой, заморожу и ударю
  молотом») он раскладывает на шаги **из словаря Engine**, а каждый шаг
  разрешает Engine. Последствия вне словаря эффектов отвергаются.
- **Прецедент-кеш:** первое решение по непокрытому случаю записывается как
  прецедент, то же взаимодействие в дальнейшем даёт тот же результат, иначе
  мир недетерминирован.
- **Лог импровизаций:** непокрытые взаимодействия логируются как бэклог
  недостающих правил.
- Риск «LLM №1 придумала → LLM №2 проверила → LLM №1 переписала»:
  избегать, не вводя цикл из двух моделей без Engine-валидации.
- Пока не строить: дорого по латентности на локальных ПК.

## 7. Архетипы и генераторы

Иерархия: **мир → регион → локация → зона → сущность → состояние**.
Генератор: **архетип → компоненты (traits) → инстанс**. Архетип
«лесопилка» = здание + источник дерева + переработка + склад; варианты вроде
«таверна + ночлег + торговля» или «таверна + руины».

**Терминология, чтобы не путать:**
- **trait/module (черта)**: набор возможностей у сущности (prayer_site, wood_source);
- **состав (composition)**: из чего вещество (порох = 5 компонентов в пропорции);
- **component в ECS**: технический термин реализации.
В документах пока использовать «черты» и «состав».

Генерация мира цепочкой: seed → биом → регион → генератор локации → архетип
→ черты → аффордансы → ресурсы → начальное состояние → канон. LLM помогает
с названиями, описаниями и вариативностью, но итог проходит Engine-валидацию.

## 8. Локации: факты, а не рельеф

Для текстового движка нужны **факты, влияющие на разрешение**, а не геометрия:

- укрытие: нет / частичное / полное;
- линия видимости: да / нет / частично;
- проходимость: свободно / узко / заблокировано;
- вместимость: один / трое / толпа;
- высота (преимущество или штраф), опасность (огонь, вода, яма), выходы.

Не «стена», а `{cover: full, los: blocked, passable: no}`; стена это рендер.
Не описывать LLM словами вроде «деревянные стены»: модель решит, что их
можно пробить. Давать свойства.

Источники: рукописные зоны (дёшево); процедурные по чанкам из seed и
параметров региона; гибрид (каркас вручную, промежутки генерируются).
**Генерация один раз и фиксация в каноне:** мир конечен, зона не меняется при
повторном входе (отличие от бесконечных миров).

## 10. Сложность (грубо)

| Блок | Сложность | Когда |
|---|---|---|
| Аффордансы (вывод из архетипа/тегов, явный список как override) | малая/средняя | рано |
| Три уровня значимости, буфер эфемерного | малая | рано |
| Классы прерываний как данные | малая | с автоматом |
| Выбор метода | малая | после аффордансов |
| Архетипы и генераторы | средняя | после базовых механик |
| Второй LLM-планировщик шагов, прецедент-кеш | средняя/большая | отложить |
